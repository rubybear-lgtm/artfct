# Changelog

All notable changes to Artifact Engine will be recorded in this file.

## [Unreleased]

### Added

- RUB-499: daily publish caps on `deploy_artifact` (new artifacts and new versions), per user and per workspace, configurable in `config/billing.php`. Identical-content republishes do not consume a slot. Over-limit responses use `quota_exceeded` with `reset_at` (next UTC midnight). Defaults: free 100/user and 300/workspace; team 200/2,000; enterprise 500/10,000.
- RUB-503: agent discovery without Cloudflare's paid features. `/.well-known/mcp/server-card.json` serves an MCP Server Card (SEP-1649/2127) built from `ArtfctServer`, `server.json` and the documented tools. The `NegotiateMarkdown` middleware returns Markdown to requests that prefer `Accept: text/markdown`, with `x-markdown-tokens` and `Vary: Accept`; this covers `/`, `/connect`, every `/connect/{tool}` page, `/blog`, every post and `/docs`. Browsers still get HTML. `AiToolSetup::guideMarkdown()` now renders the guide steps for both these pages and `llms-full.txt`.
- RUB-500: the Worker answers `GET /robots.txt` on every host it serves, asking all crawlers to stay out (`Disallow: /`, `Content-Signal: search=no, ai-train=no`). Until now the isolated artifact hosts (`*--prod.artfct.dev`, `*--stg.artfct.dev`) got robots.txt only from Cloudflare's zone-wide managed robots.txt. Once this reaches production, that managed setting can be turned off, so the app's own robots.txt (Google-Extended allowed on marketing pages, RUB-487) is the only one on the apex.
- RUB-486: the hosted server is listed in the official MCP Registry as `dev.artfct/artfct` (https://registry.modelcontextprotocol.io/v0.1/servers?search=dev.artfct/artfct). `server.json` at the repo root is the listing. Ownership of the `dev.artfct` namespace is proven by a `v=MCPv1` TXT record at the artfct.dev apex. To publish a new version, raise `version`, run `mcp-publisher login dns --domain artfct.dev` with the Ed25519 key that matches that record, then run `mcp-publisher publish`.
- Connect your agent (RUB-502, PR #59). Every setup guide, the search topics and the newest posts move to a footer sitemap, so the homepage still links all of them. `AiToolSetup::agentSetupPrompt()` is the one prompt everywhere: the agent finds its own section of `llms-full.txt` (the prompt also carries the pretty-printed server entry), makes the change or walks the person through it, confirms with `get_connection`, offers artfct-init and offers to connect the person's other agents. artfct-init now takes any coding agent (`--host`) at the `global`, `user` or `repo` level, with each agent's files checked against its docs and listed in `references/hosts.md`.
- Homepage search visibility for agent-native teams (RUB-483, PR #58). New hero ("Every agent sees what the others made.") with "AI artifact" in the subheadline, title "Artfct: shared context and AI artifacts for every agent" and a matching description. The tool names and a new guides section link every `/connect` page and the three newest posts, so crawlers reach them from `/`. The crawler fallback in `app.blade.php` is printed only when SSR did not render, so the page has one H1 and no hidden text that differs from what people see. Titles add the brand once ("— Artfct"); JSON-LD is built with `json_encode` and names Artfct with an `alternateName` and an Organization. `/blog/ai-presentations` redirects to `/blog`; `/free` has a real title and an accessible H1. `robots.txt` is served by the app: in production Google-Extended may read the site but not `/a/`, `/p/` or `/v1/`, other AI training crawlers stay out, and every other environment disallows all. Cloudflare's managed robots.txt stays on until artifact hosts serve their own (RUB-500). CLAUDE.md and DESIGN.md now name agent-native teams as the primary users.

- `artfct-init` onboarding skill (RUB-446, spec 19). It checks the connection, installs a managed `<artfct-guidelines>` block in `AGENTS.md` or `CLAUDE.md` that routes agents to `GUIDELINES.md`, `DESIGN.md` and a local `USER.local.md`, asks which tool permissions to grant and writes only approved ones (Claude Code `permissions.allow`, Codex per-tool `approval_mode`; deleting and public publishing are never granted), and keeps optional personal preferences and reviewed team imports. Re-running changes nothing that is already resolved. `get_connection` now also returns `search` (`enabled`, `indexed_artifacts`, `last_indexed_at`) so an agent can tell search turned off from nothing indexed. `npm run test:skills` runs the skill's script tests in CI. Not yet verified: Codex's `approve` setting in a live session, and the skill in a fresh Claude Code or Codex session (spec 19, unit 9).
- Publish guidance now says a published page can only load its own files (RUB-444). The page is served with `default-src 'self'; script-src 'self'`, so an inline `<script>` block, an `onclick=` attribute, and scripts, images and fonts from other sites, plus `data:` images, are blocked and the page shows without them. The rule is in `get_guidance` (publish), the `deploy_artifact` description and `html` parameter, the `artfct-publish` Agent Skill, the `artfct` skill and its authoring reference, README and AGENTS.md. Guidance version 1.0.0 to 1.1.0, now also named by `get_guidance` itself in `_meta.artfct.guidanceVersion`. This documents the behaviour and does not change what is served; RUB-444 stays open for a publish-time warning or automatic extraction of inline scripts. Checked on a live staging artifact: an inline script, a base64 image, an image from another site and a Google Fonts stylesheet are all blocked. The new `McpGuidanceTest` case fails if the Worker's isolated-origin policy builder gains `img-src`, `font-src` or an inline-script allowance, so the guidance is revisited with it.
- Launch security fixes from a clean three-reviewer pass (2026-10-18). **Worker:** the shared-origin content policy gains `sandbox allow-scripts allow-popups allow-popups-to-escape-sandbox allow-modals allow-downloads` (no `allow-same-origin`), because an artifact served at `artfct.dev/p/<id>/<path>` ran with inline scripts on the console's own origin and could act with a visitor's session; scripts still run, but in an opaque origin with no console cookies. **Billing:** Stripe events older than the last one applied to a team are ignored (new nullable `teams.stripe_event_at`), a completed checkout only upgrades a team when `payment_status` is `paid` or `no_payment_required`, events from the other Stripe mode are ignored, `customer.subscription.updated` uses the subscription's own status as a backstop for a lost invoice event, a team with a subscription cannot start a second checkout, Checkout and customer creation carry idempotency keys and allow cards only, and a test-mode key is refused in production. **App:** production never falls back to the fake AuthKit sign-in client, the OAuth consent page shows the host it returns to, and the artifact viewer and signed-in pages are `private, no-store` instead of publicly cacheable.
- Operator console for Spec 17, at `/ops`, for artfct staff only (a nullable `users.staff_at`, granted by `php artisan staff:grant {email}` and revoked by `staff:revoke`). Everyone else, including signed-out visitors, gets the ordinary 404. Outside local and testing a staff session must come through the dedicated WorkOS staff organization (`WORKOS_STAFF_ORGANIZATION_ID`); dev login never produces one. It lists tenants (search, filters, cursor paging), shows one tenant's plan, billing state, members, connections, SSO and usage against its limits, and a platform health page. Staff cannot see artifact titles, content, indexed text, comments, collections or search queries, and the console's code is checked by an architecture test not to depend on the services that read them. Every tenant view and action lands in the tenant's own audit log as "artfct staff" (no name, address or browser), with a required reason. A time-bound suppression case (legal request or abuse investigation, 90 days at most, separate `case_manager_at` privilege, hourly `ops:release-suppressed`) can withhold operator reads from the tenant's log; actions are never withheld, and every event is kept in the internal `operator_audit_events` log. Audited actions: reindex (queued), push limits, change plan or payment status, and erase a tenant (dry run, typed slug, serialised). Not shipped: impersonation, bulk actions, per-tenant custom limits, and the privacy-page disclosure and WorkOS staff organization, which are owner steps.

- Short links (RUB-439): `/a/{id}` is the one link for every artifact, at most 35 characters on `artfct.dev` with a 13-character id. Public artifacts open there for anyone (an unauthenticated `GET /v1/public/artifacts/{id}` supplies the metadata and returns the same 404 for anything that is not public); team and private links send signed-out visitors to sign in and back; `/a/{id}/v/{n}` opens a version. Old links keep working: the console open route and the Worker's shared-origin `/p/{id}/` for public artifacts redirect to `/a/{id}`, while bundle files and ephemeral links are unchanged. Every surface (console, search, collections, dashboard, MCP) now hands out `/a/{id}`.
- MCP `list_artifacts` (RUB-440): lists the team's artifacts by owner (`me`, anyone, or a member's email), sharing, collection, agent, created and updated dates, title words and kind (html, markdown, table), sorted by updated (default), created, title or most viewed, 1 to 50 per page with a cursor. Revoked and pending artifacts are excluded, private ones appear only for their owner and team admins, and each item reports its view count and whether the caller can edit it. The Worker's org list gained the matching filters and sorts; its cursor is bound to the sort it was issued for.
- Sharing levels and an artifact viewer (RUB-438). Every permanent artifact is Private (owner and team admins), Team (default) or Public (anyone with the link), and Can view or Can edit (people it is shared with may publish new versions; Public + edit lets a signed-in account from another team publish, audited with their team). The Worker enforces Private on every read path (metadata, content, versions, serving, list, export, blob download) through one module, `backend/src/sharing.rs`; unknown tiers are treated as private and every refusal is the same 404 as a missing artifact. `/a/{id}` opens an artifact in a sandboxed frame on its isolated origin under a thin header with version, owner, updated date and a Share control; team and private links from the console, search, collections and MCP now land there. `PATCH /v1/artifacts/{id}/sharing` changes sharing (owner or admin, audited as `artifact.sharing_changed`); `deploy_artifact` takes `sharing` and `edit_access` (`tier` stays as a deprecated alias). Admins can turn public links off for the team, which downgrades existing public artifacts to Team and audits each one. `php artisan artifacts:backfill-owners` gives artifacts published before owners were recorded the team owner (or the earliest admin). Access links now name their viewer, so making an artifact private stops links minted earlier; isolated origins can be framed only by the app (`ARTFCT_APP_ORIGIN`), and permanent responses are `Cache-Control: private, no-store` and `Referrer-Policy: no-referrer`. Migration 0007 is additive. Anonymous viewing of public artifacts at `/a/{id}`, version links and redirects from old links come with RUB-439.
- Artifact versioning (RUB-437). New permanent artifacts get a random 13-character stable id that survives edits; existing 32-character ids keep working and can receive versions. `POST /v1/artifacts/{id}/versions` publishes a new version (identical bytes are a no-op), `GET .../versions` and `.../versions/{n}` read history, and `.../versions/{n}/restore` republishes an old version as a new one. `/p/{id}/` serves the current version and `/p/{id}/v:{n}/` a specific one. A new version keeps the artifact's link, collections, usage history, revocation and legal hold; a pending upload never replaces the current version until complete. `artifact.version_created` re-indexes the artifact so search covers the latest version only. MCP `deploy_artifact` takes `artifact_id`, `get_artifact` takes `version`, and the console lists, opens and restores versions. Migration 0006 backfills v1 for every artifact; blob refcounts now count manifest entries across every version. Export stays current-version only. Until owners are backfilled (RUB-438), any member may publish versions of an artifact with no recorded owner.

See DOCUMENTATION.md.
- Added Spec 11 governance: an append-only Laravel audit log (`AuditEvent`, guarded against update/delete at three independent layers) covering every Laravel-controlled lifecycle action — member add/remove, role change, token mint/revoke, `auth_mode` change, console artifact revoke, retention, legal hold, and GDPR erasure — plus on-demand JSON Lines SIEM export that self-audits `export.performed`. Retention (`governance:retention`) and GDPR erasure (`governance:erase`) both default to a dry run and require `--apply` to execute; both refuse — wholly, never partially, and naming the conflict — when a referencing artifact is under legal hold. `Team.region` is set once at spec-9 provisioning and immutable afterwards, enforced regardless of call path. The Worker gained content-addressed dedupe accounting (`MemoryArtifactStore::hard_delete`, blob refcounting) and pure retention/erasure/share-link decision logic (`backend/src/governance.rs`); the D1/R2 governance routes and Laravel HTTP client are wired; `gdpr_erasure_removes_bytes_from_r2` is an ignored-by-default integration test that proves read-after-delete against isolated local Wrangler D1/R2, while real-bucket and staging governance verification remain environment gates — see DOCUMENTATION.md.
- Added Spec 12 indexing pipeline: `IndexArtifactJob` renders when raw HTML lacks visible text, extracts and chunks content, and stores extracted text for re-embedding without another render. RUB-316 replaces the fail-closed providers with Cloudflare Browser Rendering of signed artifact URLs, batched 1024-dimensional Qwen3 embeddings, and a tenant-scoped pgvector store on Railway Postgres. Render failures retry with backoff and dead-letter to `ArtifactIndexingFailure`; artifact deletion removes its chunks. The Worker-to-Laravel `artifact.created` event can enqueue indexing when `INDEXING_ENABLED` is enabled. Staging web, queue, scheduler, and Worker now carry the code, and the pgvector migration ran. A public two-file artifact served its HTML and relative JavaScript with matching bytes, and its `artifact.created` event reached Laravel. Indexing remains disabled until the staging Cloudflare API token that currently returns 401 is replaced, the real providers pass a smoke test, and the full event-to-search flow is verified. The original Vectorize cost probe was superseded by the pgvector architecture decision.
- Added Spec 13 retrieval: `search_artifacts` and the authenticated `/api/search` endpoint resolve the org from its JWT, combine pgvector cosine and PostgreSQL full-text results with reciprocal rank fusion, remove revoked or inaccessible artifacts before Workers AI reranking, and apply recency, provenance, usage, and canonical-collection ranking. Repo/agent/since filters remain available. Results contain a short snippet and summary, never the full bundle, and every search writes a `search.performed` audit event. The earlier sub-500ms measurement used 1,000 fake artifacts; real-provider staging latency has not yet been measured.
- Added Spec 14 billing, quotas and branded console: a `plan` (`team`/`enterprise`) column gated through exactly one shared call site, `PlanGate::requireEnterprise()` — SIEM export, retention config, and moving `auth_mode` beyond `authkit` are all refused on `team` with a clear upgrade message, never a 500, and structurally verified to have no second call site. `QuotaService` warns at 80% and refuses new artifact creation at 100% (`errorCode: quota_exceeded`) or on a bundle above the tenant's per-artifact ceiling (`errorCode: bundle_too_large`, below spec 4's absolute ceiling) or a past-due payment — never touching an existing artifact's row or the serving path. `BillingService` counts seats from active memberships, applies Stripe's checkout/payment-failed/payment-succeeded events (methods, not yet a live webhook route), and degrades an org to read-only on payment failure without deleting anything, restoring create access automatically on the next success. A tenant's custom hostname is unique at the database level, not merely by application check. The Worker-side create-path wiring for quota enforcement, a live Stripe webhook route, and a billing settings UI were not built this session — the fourth occurrence of the same Worker/Laravel boundary gap this run keeps hitting; see DOCUMENTATION.md.

- Added Spec 15 Slack: unfurl richness scales with an artifact's sharing level as a pure function with no viewer parameter — public shows full metadata, domain-restricted shows title only, org-private (and anything the sharing lookup doesn't recognize) always renders a bare card, since Slack fetches and caches an unfurl once per URL rather than once per viewer. `/artfct <query>` resolves a Slack workspace to a team and a Slack user to a member of that specific team (via `external_identities`, provider `slack`) before running spec 13's `SearchService`, always responding `ephemeral` — an unlinked user or one linked to a different org gets a connect prompt, never another org's results. An agent can post an artifact to a Slack channel only if that org token's allowlist includes it, rate-limited per channel and refused (not queued) past the cap. Both unfurl and search write audit events. Slack's own request-signature verification is not implemented (no live Slack app to verify a real signature against) — named explicitly in DOCUMENTATION.md, not silently skipped.

- Added Spec 16 collections and usage ranking: `UsageScorer` combines distinct views, Slack shares, and retrieved-then-opened events with a 30-day half-life; superseded artifacts score zero. `search_artifacts` can scope to a named collection, and canonical membership adds a ranking boost. Members can manage collections, while canonical pinning is Admin-gated. The Worker now emits `artifact.viewed`; Laravel records view usage and correlates a later open with a recently served search result. Anonymous distinct-view scoring uses a daily-salted pseudonymous visitor key when its secret is configured.

### Changed

- RUB-454: CI runs its PHP work as three jobs that no longer wait for each other — `php_static` (Pint `--parallel`, Larastan, frontend format/lint/types/build/route checks, dependency audits), `pest_unit_feature` (Pest `--parallel` over the Unit and Feature suites, then the pgvector integration test) and `pest_browser` (Pest `--parallel` over the browser suite, Chromium only, `~/.cache/ms-playwright` cached). `application` stays the required check on `main` as an aggregate gate over the three. Every PHP CI job turns on CLI opcache: Pint alone was 141 s in CI against 0.64 s for the same 397 files with it, and `--parallel` on top of that. The pre-commit and pre-push hooks and `composer test` use the same flags, so the full suite is 117 s serial against 31 s parallel locally. Three helpers that a test file declared and another file used (`STABLE_ARTIFACT_ID`, `linkSlackUser()`, `consoleUrl()`) moved to `tests/Pest.php`: under `--parallel` each worker only loads its own files, so a cross-file helper is an "undefined function/constant" error.
- RUB-454: the MCP end-to-end job is skipped on pull requests whose changed files are all docs, Markdown, `resources/js`, `resources/css`, `tests/Browser` or `public/images` (a skip list, so any other file still runs it), and it always runs on pushes to `main` and `develop`. Its cargo cache now stores the workspace `target/` as well as `backend/target`; before, the Worker build and the Rust test compile restored nothing.
- Hosted MCP sessions are kept for 14 days. The CLI and local MCP server are retired; only the hosted OAuth MCP is supported (RUB-432).
- RUB-402: Railway service settings now live in `.railway/railway.ts` (Infrastructure as Code) and the deprecated `railway.json` is removed ahead of Railway's 2026-12-01 Config as Code cutoff. `staging-web` carries its start command, `/up` healthcheck, timeout and restart retries in the IaC; staging is applied and plans clean. Production is unchanged.
