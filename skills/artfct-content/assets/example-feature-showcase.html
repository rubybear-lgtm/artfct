Shared knowledge

Every AI tool on your team starts from the same store

The artfct team · Last updated 2026-10-08 · 5 min

Most teams run two to four AI tools, and each one keeps its own history. A report your product manager made in Cursor is invisible to an engineer in Claude Code, so the next agent rebuilds work the team already paid for. Artfct gives those tools one store of finished work, and any connected tool can find it.

Why does each tool keep its own history?

An AI tool remembers the conversations held inside it. That is a product boundary, not an oversight: a vendor indexes its own output and has no reason to index a competitor's. The consequence is that the unit of memory is the tool, while the unit of work is the team.

Work therefore gets redone. The engineer asks for a churn breakdown the analyst already produced a month ago, and gets a second, slightly different one. Two versions of the same number is worse than one, because nobody can tell which is current.

What does a connected tool actually see?

When someone publishes a page, report, table or document, Artfct stores it with its provenance: which agent produced it, which model, and where there is one, the repository and commit. Every connected tool can search that store.

Retrieval is what makes it useful rather than merely tidy. An agent asks a question in plain language, gets back summaries with a link to each artifact, and says which ones it used. The docs describe the tools a connection exposes.

How does a teammate find the same thing?

The same store answers people. Someone describes what they are looking for and gets matching artifacts back, without knowing a filename or which tool made it. Results are ranked by what the team has actually used, so the version people keep opening comes first.

Sharing stays one step. Publishing produces a link; the same link opens in Slack for a colleague and is visible to an agent through retrieval.

What does connecting a tool involve?

One person adds the server to each tool and signs in once. Claude Code, Codex, OpenCode and Antigravity are verified end to end; the setup guides cover Claude, ChatGPT, Cursor, VS Code, Windsurf and Zed as documented paths.

Members install nothing. If you are the person setting this up, the full reference lists every tool and what each one is allowed to do.

How do you keep it from becoming a dumping ground?

Publishing is deliberate, and collections are how a team marks what mattered. Pinning an artifact to a collection lifts it in later results, which turns the store from an archive into a record of the way the team works.

Usage does the rest. An artifact nobody opens stops outranking one that gets used.

What this does not do

  • It does not write or edit documents for you. Artfct stores and finds what an AI already made.
  • It does not accept arbitrary office files. An artifact is something an AI made that renders as a page.
  • A tool that can only start programs on your computer cannot connect, because Artfct runs as a hosted server.
  • It does not make a model smarter. It moves finished work between tools, not reasoning.

Questions

Does a team member need to install anything?

No. The person who connects the tools signs in once, and everyone else just uses what is shared.

Which tools are supported today?

Any tool that can reach a remote server. Claude Code, Codex, OpenCode and Antigravity are verified; several others have documented setup.

Can an agent see something that was not shared?

No. An artifact is visible to a tool only when it is shared with the team or published publicly.

What happens when two tools produce the same thing?

Identical content resolves to one artifact rather than a duplicate, and a later version of the same artifact keeps the original link.

How do we get rid of something?

An admin can revoke or delete it from the console, and the action is recorded in the audit log.
